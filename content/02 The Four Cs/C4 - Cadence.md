The first three C's give you an assistant that knows you, can reach your work, and can do real tasks. But so far it still waits for you to ask. Cadence is the last piece: it lets the work run on a schedule, so things happen without you starting them.

## Letting it run on a schedule

Instead of opening the AI and asking, you set a task to run on its own at a set time. In Claude, you just ask in plain words: "Run the morning brief recipe every weekday at 6 am." It becomes a **scheduled task**. You can see, pause, and edit your scheduled tasks in the app.

A few that physicians find useful right away:

- **Morning brief:** before clinic, a short note of what your day holds and what needs prep.
- **Evening inbox sort:** each evening, new notes in `00 Inbox` and today's daily note get read, action items pulled out, and everything filed into the right project.
- **Weekly digest:** every Sunday, a summary of the week and a draft plan for the next.
- **Literature watch:** every Monday, new papers on your research topics, summarized against your questions.

Each runs while you are doing something else. You just read the result. Ready-made versions are on the [[Scheduled Recipes]] page.

## Three ways a task can start

- **On a clock:** at a set time, like every weekday at 6 am, or Sunday at 7 pm.
- **On an event:** when something happens, like a new file in a folder or a new email.
- **On its own results:** it checks how its earlier work did and adjusts, like noticing which draft replies you actually sent.

You will get most of the value from the first one. Start there.

## Start slow, then speed up

More often is not better. A task that runs every hour when once a day would do just creates noise.

1. Pick the slowest schedule that would still be useful.
2. Let it run a few times and read the results closely.
3. Only speed it up, or let it act without your approval, once you trust the output.

Trust is built one reliable run at a time. A scheduled task should almost always produce a **draft or a report**, not take an irreversible action. Let it write the brief; you send the emails.

## Watch for silent drift

Scheduled work has one quiet risk: it can break without telling you. A tool changes, a folder moves, and the task keeps running but stops producing anything useful.

- For the first few weeks, skim each result when it arrives.
- Once a task is steady, a quick monthly check is enough.
- If a result looks empty or wrong, fix the cause rather than ignoring it. See [[When AI Gets It Wrong]].

## You now have the full picture

That is the Four C's. **Context** so the AI knows you. **Connections** so it can reach your work. **Capabilities** so it can do real tasks. **Cadence** so it runs on its own. Each builds on the last, and together they turn AI from a search box into a setup that compounds.

Build it one piece at a time. Make your `CLAUDE.md`. Add one connection. Save one recipe. Put one task on a schedule. Then repeat. Within a few weeks you will have something no generic tool could give you, because it is built around your knowledge and your practice.

## What to do next

- Put one task on a schedule. The morning brief or weekly digest is a good start.
- Read the first several runs before trusting it.
